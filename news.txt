1. OVERVIEW
================================================================================

This report covers the full migration of the TSSOSA alumni website backend
from Prisma ORM (connecting to a local/Supabase-hosted PostgreSQL) to the
Supabase JavaScript client (@supabase/supabase-js) for all database operations
and authentication.

The migration touched 24 files across both backend and frontend:
  - 1,663 lines added
  - 1,849 lines removed
  - Net: ~186 lines fewer (cleaner codebase)

Key architectural changes:
  - Prisma ORM entirely removed
  - Supabase service-role client handles all DB queries (backend)
  - Supabase Auth replaces custom JWT + bcrypt authentication
  - Frontend uses Supabase client for session management

================================================================================
2. WHAT WAS THE PROBLEM
================================================================================

Before this migration:
  - The DATABASE_URL pointed to a Supabase-hosted Postgres but used Prisma
    ORM to query it
  - Authentication was custom: bcrypt for password hashing, jsonwebtoken for
    access/refresh token creation and verification
  - Passwords were hashed with bcrypt(12), stored in a password_hash column
  - Custom refresh token rotation was implemented via a refresh_tokens table
  - The @supabase/server package was installed but NEVER used (empty file)
  - Supabase keys in .env were present but never referenced in code
  - The DATABASE_URL had a malformed/redacted password causing connection
    failures (P1001: Can't reach database server)

After this migration:
  - Supabase JS client handles ALL database operations via PostgREST
  - Supabase Auth handles registration, login, session management, passwords
  - No more bcrypt, no more custom JWT, no more refresh token management
  - The Supabase service-role key provides full database access (bypasses RLS)

4.3  AUTH MIDDLEWARE (src/middleware/auth.js)
─────────────────────────────────────────────
  BEFORE:
    - Extracts Bearer token from Authorization header
    - jwt.verify(token, config.jwt.secret)
    - Attaches decoded payload to req.user
    - requireAdmin checks req.user.role === 'admin'

  AFTER:
    - Extracts Bearer token from Authorization header
    - Calls supabase.auth.getUser(token) to verify the JWT via JWKS
    - Attaches user object { id, email, role, app_metadata, user_metadata }
    - requireAdmin checks req.user.role === 'admin' (same logic)

4.4  AUTH CONTROLLER (src/controllers/authController.js) — FULL REWRITE
───────────────────────────────────────────────────────────────────────
  register():
    BEFORE: bcrypt.hash → prisma.user.create → prisma.member.create →
            prisma.setMember.create → jwt.sign → prisma.refreshToken.create
    AFTER:  supabase.auth.admin.createUser({ email, password, user_metadata,
            app_metadata }) → supabase.from('users').insert →
            supabase.from('members').insert →
            supabase.from('set_members').insert →
            supabase.auth.admin.createSession

  login():
    BEFORE: prisma.user.findUnique → bcrypt.compare → jwt.sign →
            prisma.refreshToken.create
    AFTER:  supabase.auth.signInWithPassword({ email, password }) →
            Check user.user_metadata.is_verified

  refresh():
    BEFORE: jwt.verify(refreshToken) → prisma.refreshToken.findUnique →
            revoke old → create new → jwt.sign
    AFTER:  supabase.auth.refreshSession({ refresh_token })

  logout():
    BEFORE: prisma.refreshToken.updateMany (revoke)
    AFTER:  supabase.auth.admin.signOut(userId)

  me():
    BEFORE: prisma.user.findUnique({ include: { member: { include: ... } } })
    AFTER:  supabase.from('users').select → supabase.from('members').select →
            supabase.from('set_members').select (with joins)

  updateProfile():
    BEFORE: prisma.user.update → prisma.member.upsert
    AFTER:  supabase.from('users').update → supabase.from('members').update/insert

  changePassword():
    BEFORE: bcrypt.compare → bcrypt.hash → prisma.user.update →
            prisma.refreshToken.updateMany (revoke all)
    AFTER:  supabase.auth.signInWithPassword (verify current) →
            supabase.auth.admin.updateUserById({ password: newPassword })

  REMOVED:
    - bcrypt import and all bcrypt.hash/bcrypt.compare calls
    - jsonwebtoken import and all jwt.sign/jwt.verify calls
    - hashToken() function (SHA-256 for refresh tokens)
    - generateAccessToken() function
    - generateRefreshToken() function
    - All RefreshToken table operations

  Prisma Pattern                          → Supabase Pattern

    where, include, skip, take             .select('*, user:users(...),

                                           .eq('is_active', true)
                                           .range(skip, skip+take-1)

    where: { id }, include                 .select('...')

  prisma.graduationSet.create({          → supabase.from('graduation_sets')
    data                                   .insert({...}).select().single()

  })

4.6  ALL OTHER CONTROLLERS (announcement, milestone, payment, dues,
     election, exco, admin, webhook)
─────────────────────────────────────────────────────────────────────
  Same conversion pattern applied to all 9 remaining controllers:
    - All prisma.X.findMany → supabase.from('X').select(...)
    - All prisma.X.findUnique → supabase.from('X').select(...).single()
    - All prisma.X.create → supabase.from('X').insert(...).select().single()
    - All prisma.X.update → supabase.from('X').update(...).eq(...).select()
    - All prisma.X.delete → supabase.from('X').delete().eq(...)
    - All prisma.X.count → supabase.from('X').select('*', { count: 'exact', head: true })
    - All prisma.X.upsert → supabase.from('X').upsert(...)
    - All prisma.$transaction → sequential Supabase calls
    - Prisma include syntax → Supabase embed syntax: select('*, rel(*)')

  Supabase error codes used:
    - PGRST116 = "not found" (replaces Prisma P2025)
    - 23505 = unique constraint violation (replaces Prisma P2002)

──────────────────────────────────────────────────
  BEFORE:

    - getAccessToken() → localStorage.getItem(TOKEN_KEY) [synchronous]
    - clearAccessToken() → localStorage.removeItem(TOKEN_KEY)

  AFTER:

    - getAccessToken() → async, returns supabase.auth.getSession()?.access_token

      syncAccessToken = session?.access_token ?? null;
    });

10. BREAKING CHANGES & MIGRATION NOTES
================================================================================

  ⚠️  EXISTING USERS:
    Users who registered with the old bcrypt system will NOT be able to
    log in. Supabase Auth uses its own password storage. You need to:

    Option A: Re-register all existing users via Supabase Auth
    Option B: Use supabase.auth.admin.createUser() to migrate users
              (passwords cannot be transferred — users must reset)
    Option C: Use the Supabase SQL editor to create auth users from
              the existing users table

  ⚠️  REFRESH TOKENS:
    The old refresh_tokens table is no longer used. Supabase Auth
    manages its own refresh tokens in auth.refresh_tokens. You can
    drop the public.refresh_tokens table if desired.

  ⚠️  ADMIN ROLE:
    Admin role is now stored in Supabase user metadata:
      - app_metadata.role = 'admin'
      - user_metadata.role = 'admin'
      - public.users.role = 'admin' (kept for queries)

    To make a user admin, update via Supabase dashboard or use:
      supabase.auth.admin.updateUserById(userId, {
        app_metadata: { role: 'admin' },
        user_metadata: { role: 'admin' }
      })

  ⚠️  IS_VERIFIED FLAG:
    Now stored in user_metadata.is_verified instead of a column on
    the users table (though users.is_verified is still kept for
    backward compatibility with queries).

11. HOW TO GET IT RUNNING
================================================================================

  1. Fill in real Supabase keys:
     - backend/.env: SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_KEY
     - frontend/.env.local: NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY

  2. Ensure your Supabase project has all 14 tables with the correct
     column names (snake_case, matching the Prisma schema's @@map names).

  3. Start the backend:
     cd backend && npm run dev

  4. Start the frontend:
     cd frontend && npm run dev

  5. The old Prisma scripts (db:push, db:migrate, etc.) no longer work.
     Use the Supabase dashboard or SQL editor for schema management.
